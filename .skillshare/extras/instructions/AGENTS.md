자연스럽고 다정한 말투로 말한다.

## 커밋 메시지 규칙

- 모든 프로젝트의 기본 커밋 제목은 `[분류] 한글 메시지` 형식으로 작성한다.
- 대괄호에는 아래 영문 소문자 분류 하나만 넣고, 닫는 괄호 뒤에 공백 한 칸과 메시지를 적는다. 콜론은 붙이지 않는다.
- 메시지는 무엇을 추가·수정·삭제했는지 한글로 간결하고 구체적으로 작성한다. 필요한 기술명·제품명·식별자는 원문을 유지한다.
- `feat:`·`fix:` 같은 Conventional Commits 접두어 대신 이 대괄호 형식을 사용한다. 기능 추가 분류는 `feat`가 아닌 `feature`로 통일한다.
- 독립적인 기능·스크립트·글·리뷰는 의미 단위로 커밋을 나눈다. 해당 작업의 안내 문서·검증·히스토리는 같은 커밋에 포함한다.
- 분류는 주된 변경 목적을 기준으로 고른다. 기능과 관련 문서를 함께 수정했다면 `feature` 또는 `fix`를 사용하고, 문서만 바꾸면 `docs`를 사용한다.
- 사용자가 해당 작업에서 다른 커밋 형식을 명시하면 그 요청을 우선한다. 이 규칙 자체가 커밋이나 푸시를 자동 승인하는 것은 아니다.

| 분류       | 적용 대상                                              |
| ---------- | ------------------------------------------------------ |
| `feature`  | 기능·자동화·스크립트 추가 또는 동작 확장               |
| `fix`      | 오류·잘못된 동작 수정                                  |
| `docs`     | README, 사용법, 설정 안내, 작업 기록 등 문서 작성·수정 |
| `blog`     | 블로그 글 작성·수정                                    |
| `review`   | 상품·서비스 후기 등 리뷰 콘텐츠 작성·수정              |
| `refactor` | 동작을 유지하는 코드 구조 개선                         |
| `style`    | 코드 서식·들여쓰기 등 동작에 영향 없는 형식 변경       |
| `test`     | 테스트 추가·수정                                       |
| `perf`     | 성능 개선                                              |
| `build`    | 빌드 도구·패키징·의존성 구성 변경                      |
| `ci`       | CI/CD 워크플로 변경                                    |
| `chore`    | 개발 환경·도구·저장소 유지보수                         |
| `task`     | 위 분류에 해당하지 않는 일반 작업 산출물               |
| `revert`   | 이전 커밋 되돌리기                                     |

예시:

- `[feature] 날씨 음성 안내 스크립트 추가`
- `[fix] 환율 응답이 비어 있을 때 재시도하도록 수정`
- `[docs] 스크립트 적용 방법 정리`
- `[blog] 거실 스피커 연동 구축기 작성`
- `[review] 무선 청소기 사용 후기 작성`
